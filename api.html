API & Integrations

Connect EduToolsFactory to your own tools, dashboards and automation.

The EduToolsFactory Remote API lets you manage tests, surveys and assignments from your own tools or integration layer. You can create and update tests, attach content URLs, fetch MCQ items, and query survey definitions and assignments linked to your organization.

All endpoints are protected by token-based access, layered defenses and rate limiting. See Security & Compliance for how we secure delivery.

Remote API overview

  • Manage tests (create, update, delete).
  • Attach content URLs used to generate MCQs.
  • Fetch basic test metadata and published MCQ items.
  • Manage surveys and survey questions.
  • Read survey assignments and response counts per assignment.
curl -X GET "https://edutoolsfactory.com/api/remote/tests" \
  -H "Authorization: Remote YOUR_REMOTE_TOKEN_HERE" \
  -H "Accept: application/json"

Remote endpoints

GET /api/remote/tests

List tests, their URLs, and published MCQ items. Requires Remote token; per-user + per-IP rate limiting (429 on abuse).

Headers: Authorization: Remote <token> 

curl -X GET "https://edutoolsfactory.com/api/remote/tests" \
  -H "Authorization: Remote <token>" \
  -H "Accept: application/json"
POST /api/remote/tests

Create or update a test and attach URLs. Token-scoped to owner; request firewall filters malicious payloads.

Headers: Authorization: Remote <token>, Content-Type: application/json

curl -X POST "https://edutoolsfactory.com/api/remote/tests" \
  -H "Authorization: Remote <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{ "name": "My Test", "urls": ["https://example.com/a","https://example.com/b"] }'
POST /api/remote/tests/{testId}

Add additional URLs to an existing test. Remote token required; rate limiting enforced.

Headers: Authorization: Remote <token>, Content-Type: application/json

curl -X POST "https://edutoolsfactory.com/api/remote/tests/{testId}" \
  -H "Authorization: Remote <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{ "urls": ["https://example.com/a2","https://example.com/b2"] }'
DELETE /api/remote/tests/{testId}

Delete a test belonging to the current token owner. Subject to per-user + per-IP throttle (429).

Headers: Authorization: Remote <token> 

curl -X DELETE "https://edutoolsfactory.com/api/remote/tests/{testId}" \
  -H "Authorization: Remote <token>" \
  -H "Accept: application/json"
DELETE /api/remote/tests/{testId}/urls/{urlId}

Remove a single URL from a test. Requires Remote token and obeys rate limiting.

Headers: Authorization: Remote <token> 

curl -X DELETE "https://edutoolsfactory.com/api/remote/tests/{testId}/urls/{urlId}" \
  -H "Authorization: Remote <token>" \
  -H "Accept: application/json"
GET /api/remote/surveys

List surveys, questions, assignments and response counts. Remote token scoped to owner; 429 returned on abuse.

Headers: Authorization: Remote <token> 

curl -X GET "https://edutoolsfactory.com/api/remote/surveys" \
  -H "Authorization: Remote <token>" \
  -H "Accept: application/json"
/remote/exam/{slug}

Public exam delivery (GET show/state/full, POST answer/skip/finish). Protected by multiple layers (firewall + rate limits).

Headers: Authorization: Remote <token> for managed flows; X-Session-Token for per-attempt state/answer/finish; Accept: application/json when posting answers.

curl -X GET "https://edutoolsfactory.com/api/remote/exam/{slug}/state" \
  -H "Authorization: Remote <token>" \
  -H "X-Session-Token: <session_token>" \
  -H "Accept: application/json"

curl -X POST "https://edutoolsfactory.com/api/remote/exam/{slug}/answer" \
  -H "Authorization: Remote <token>" \
  -H "X-Session-Token: <session_token>" \
  -H "Accept: application/json" \
  -d '{ "mcq_item_id": 971, "answer_key": "A" }'
/remote/survey/{slug}

Public survey delivery (GET show/full, POST answer/finish). Same layered protections; used for taking surveys via browser or extension links.

Headers: Authorization: Remote <token> for managed flows; X-Session-Token when continuing a session; Accept: application/json for submits.

curl -X GET "https://edutoolsfactory.com/api/remote/survey/{slug}/full" \
  -H "Authorization: Remote <token>" \
  -H "X-Session-Token: <session_token>" \
  -H "Accept: application/json"

curl -X POST "https://edutoolsfactory.com/api/remote/survey/{slug}/answer" \
  -H "Authorization: Remote <token>" \
  -H "X-Session-Token: <session_token>" \
  -H "Accept: application/json" \
  -d '{ "question_id": 5, "answer": "C" }'

All endpoints respect token scoping (where applicable) and layered protections (firewall + per-IP/per-user limits). See Security & Compliance for details.

Authentication & rate limiting

All Remote API calls must include an Authorization: Remote <token> header. The token is scoped to a single EduToolsFactory account; all queries are restricted to data owned by that account. Layered protections (firewall + per-IP/per-user rate limits) apply across endpoints. For more, see Security & Compliance.
